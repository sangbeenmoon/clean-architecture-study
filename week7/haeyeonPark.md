## 핵심 내용 요약
- 데이터베이스는 세부사항이다. 필요에 따라서, 혹은 마케팅적인 이유로라도 바뀔수 있음.
- 웹은 세부사항이다. ui와 업무규칙을 분리해야한다.
- 프레임워크는 세부사항이다. 
- 패키지 구분이 없으면 모두 그냥 계층형 아키텍처로 보인다. -> 패키지 구분에 따라 4가지 방식 
1. 계층기반 패키지 - 유사한것들끼리 나눈 구조. 도메인이 안보인다.
2. 기능기반 패키지 - 도메인별로 패키지를 나눈 구조.
3. 포트와 어댑터 - 세부사항과 업무규칙을 포트와 어댑터로 의존성 역전하여 분리.
4. 컴포넌트 기반 패키지 - 업무규칙과 데이터 계층이 하나의 컴포넌트로 합쳐짐. 계층기반에서 controller가 db바로 호출하는것을 방지할순 있음. 하나의 서비스단위가 될수있는 단위
- 인프라끼리도 호출해서는 안된다.
