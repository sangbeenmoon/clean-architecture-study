## 핵심 내용 요약
12장

컴포넌트 = 배포단위. 독립적으로 배포, 개발이 가능해야함

13장

무엇을 같이 묶고 분리할것인가
REP = 함께 배포되고 재사용할수있는 단위 
CCP(그나마 가장 와닿음) = 같은 이유로 변경되는 클래스는 한 컴포넌트에 (SRP와 유사)
CRP = 함께 쓰이지 않는 클래스는 분리 
이 셋은 트레이드오프

14장

ADP - 순환 의존 금지
-> DIP로 의존성 역전, 컴포넌트 하나 만들어 공통 의존 추출 

SDP - 안정된 방향으로 의존 
-> 변화가 잦은 컴포넌트에 안정적인 컴포넌트가 의존하면 안된다

SAP - 안정적일수록 추상화해야한다

## 인상 깊은 내용
> 특히 기억에 남거나 공감된 부분

불안정한 컴포넌트에 안정적인 컴포넌트가 의존하면, 코드 한 줄 안 바꿔도 변경이 어려워진다
-> 내가 의도적으로 쉽게 바꿀 수 있게 만든 모듈이, 누군가 의존성 하나 걸어놓는 것만으로 경직된다. 코드가 아니라 의존성 구조가 변경 용이성을 결정한다는 관점이 인상적이다.

## 의문이 드는 내용 / 동의하지 않는 내용
> 책의 주장에 대한 비판적인 관점

컴포넌트는 독립적으로 배포 가능한 단위. 컴포넌트를 어디까지로 봐야할까?...
우리팀은 Next.js 모노리스, 모듈별로 잘 나눠져있지만 독립 배포는 불가. build하면 전부 하나로 묶임
=> 이건 나쁜구조인가?  A 모듈을 수정하는데 B모듈을 건드릴 필요없으면 괜찮은것 아닌지? 독립 배포보단 독립 개발가능이 더 실용적인 기준은 아닌지. 변경의 영향범위를 최소화 할수있도록 의존성관리에 힘쓴다면 괜찮지 않을지..

TypeScript/Next.js 모노리스 환경이다보니.. 배포 단위가 하나라 모듈 간 버전 독립성이란 개념이 잘 안와닿았음.
